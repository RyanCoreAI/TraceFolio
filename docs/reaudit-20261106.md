# Second audit: preserve evidence review boundaries

Verified against PR #1 head `c66dfadff13cd1ca4386267d0da02421cdff1d33`.

The JD matcher and portfolio claim pages rejected only `INVALID`, so `NEEDS_REVIEW`, null, and unknown validation states could become positive evidence. Both paths now require `VALID`, a nonblank quote, and a source URI. Raw retrieval fallback also checks the tenant's review state for the actual retrieved chunk IDs, including claims outside the ranked top-200 window. A failed review lookup yields no positive fallback evidence.

New exports also check the evidence IDs in saved JD matrices and interview-defense cards. If a current review record blocks any referenced chunk or claim, export returns 409 with instructions to regenerate the match and draft. Initial claim-boundary regression had three failures out of four, and the saved-export regression had two failures out of three. The final Maven package passed all 63 tests with no skips.

Existing saved JD matrices, resume drafts, and export files remain historical snapshots. The checks apply to new matches and exports. `VALID` represents the application's validation state. TraceFolio remains a local single-user prototype.
